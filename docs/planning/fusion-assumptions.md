# Fusion assumptions (NHANES, MIMIC-IV, MIMIC-IV-ED, MIMIC-IV-ECG, WESAD)

These assumptions support the **signed Title Phase** project: *A Deep Learning Framework for Early Detection of Chronic Kidney Disease: Integrating Multi-Modal Data from Wearable Devices and Clinical Records with Explainable AI* (supervisor: Dr. Naznin Sultana). Work stays within **public** wearable and EHR datasets, **risk prediction and interpretation only** (no therapeutic recommendations), and **simulated** clinical decision support — not live hospital EMR integration.

This project does **not** merge patient records across NHANES, MIMIC-IV (including **MIMIC-IV-ED** when used as a separate ED-focused EHR source), and WESAD: cohorts outside MIMIC’s own modules have disjoint identities and incompatible schemas, so there is no valid row-level join across NHANES or WESAD. Within PhysioNet MIMIC products, **MIMIC-IV**, **MIMIC-IV-ED**, and **MIMIC-IV-ECG** may be linked where documentation allows (e.g., `subject_id` / study or encounter keys), while **WESAD** and **NHANES** remain **disjoint** from those identities. Integration is **architectural**—a shared multimodal pipeline with **dataset-specific training**—and **representation-level** fusion (e.g., concatenation or attention over **z_ehr**, **z_ecg**, and **z_wear** where each is defined), not one global merged table spanning NHANES and ambulatory wearables with MIMIC identities.

**MIMIC-IV-ECG** provides **diagnostic 12-lead ECG waveforms** (WFDB) that PhysioNet documents how to link to **MIMIC-IV** patients (e.g., `subject_id`). This is **not** a consumer wearable dataset: it is **hospital ECG**. In your thesis it **completes the waveform / physiology side for the MIMIC cohort**—you can train **paired EHR + ECG** models where both modalities exist for the same individual, which you **cannot** do between NHANES and WESAD. Use an ECG encoder that outputs **z_ecg**; fuse **z_ehr** + **z_ecg** for MIMIC-based experiments, with the same **missing-modality** story if an admission has labs but no ECG or vice versa.

**WESAD** carries no CKD labels; it is used to learn a **wearable / ambulatory encoder** (self-supervised or proxy supervised tasks) that outputs **z_wear** from **continuous multichannel** data (including **portable ECG**, EDA, temperature, etc.). That embedding encodes **ambulatory** physiology, which you justify as **supportive** context when fused with clinical evidence—**not** a substitute for creatinine, eGFR, or diagnostic 12-lead context from MIMIC-ECG. **Optional-modality deployment** means the system must run when only EHR/structured data exist: train with **missing-modality handling** (masking, zero-padding with learned gates, or EHR-only baseline) so CKD predictions remain defined without waveforms; when extra towers (**z_wear**, **z_ecg**) are available, fusion improves or calibrates risk according to your validation protocol.

## Regulatory and deployment scope

**NHANES**, **MIMIC-IV** (including **ED** and **ECG** modules where used), and **WESAD** are **real** public datasets—population survey, de-identified ICU/hospital derivatives, and research-grade wearable recordings—not synthetic “toy” data. Use of these sources is governed by **research** rules (e.g., PhysioNet **credentialing** and data-use agreements, NHANES analytic guidelines), which makes the work **secondary analysis of real-world data**, not a live clinical product. **Medical device regulation**, hospital governance for **live decision support**, or **IRB-approved primary data collection** at your site are **out of scope** for this FYDP as written: the deliverable is **methodologically rigorous** multimodal modeling and XAI, plus a **prototype** CDS-style visualization, **without** therapeutic recommendations or EMR deployment. Framing for examiners: the project demonstrates a **plausible architecture** and **evidence from public benchmarks**; it does **not** claim clearance, certification, or readiness for unsupervised clinical use. Any future operational use would require separate legal, clinical, and validation workflows beyond this Title Phase.
